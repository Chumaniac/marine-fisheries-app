# 受理阶段与存储预算（当前源码）

在“同步与运维”选择“检查运行状态”，沿用既有outbox、operations和ledger状态读取；不增加轮询、重试、识别或清理。新workload字段只向当前租户操作员/审计员提供明细，其他身份显示需有权限者核对；设备令牌原有端点限制不变。

八项预算直接复用现有准入策略：事件500000、活跃outbox100000、标签/批次各10000、人工复核1000/记录图像256MiB、边缘受理/证据各1000。活跃outbox包含pending/action_required/dispatching/outcome_unknown，不含已发布。80%为界面检查提示，达到预算不代表自动删除或新增权限。图像字节仅来自记录中的manifest，不是磁盘实际占用或证据文件有效性验证。

容量计数按tenant索引/聚合读取。复核图像汇总在SQLite内最多处理1001行、每行64KiB安全JSON投影，仅提取有限manifest字节；不把正文或预测载荷带入Python。坏/过大/缺失元数据或缺表返回used:null/status:unknown，不冒称0或尚有预算。新增元数据检查最多2个实际读取同时工作，忙时保留旧运维功能并将新增观察标为未核对。

受理阶段是当前本地记录，不是完整现场投递结论。counts覆盖当前租户的received/review_pending/published/review_rejected及未知阶段；界面最多展示20条未结束阶段示例。现有表没有可靠受理时间和失败原因，所以时间明确null、原因为not_recorded；不能据此推断“已卡住多久”或“分类失败”。received也可能仍在正常处理。下一步是核对原设备journal及已有事件，或去既有人工复核列表，不自动重投结果未知的原请求。已发布阶段记录也不等于独立链上/证据认证。

观察函数不更新admission、outbox、业务事件或模型；既有operations心跳/告警检查行为保持。GET不构成重试、对账确认、删除、归档或模型授权。前端以读取ticket和当前actor scope丢弃较旧/换账号回应，退出清空新告警与预算；失败/旧API缺字段时显示待核对，不保留为当前成功。三个既有运维读取先完整校验后一次替换；摘要缺计数、坏列表或后续链状态读取失败时，摘要和操作列表一并清空并显示暂不可核对，不以0兜底。原表单、队列、批次选择、人工重试/对账权限保持。

新功能不迁移已有数据表、不调用模型/Provider、不改变原准入上限或正式安装版。现场设备、真实海域/鱼种、互操作和链服务验收仍独立。
