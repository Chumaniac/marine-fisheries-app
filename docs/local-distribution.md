# 海洋渔业本机应用 0.4.1

私有 GitHub Release 提供可直接启动的本机应用。源码、安装包、配置和数据不转为公开，不包含账号、模型权重、原图、密钥或旧数据库。

## 安装与入口

下载私有 v0.4.1 的 ZIP 和 checksums.txt，核对 SHA-256 后解压到自己的应用目录。需要 Python 3.12 与 uv；Mac 双击 `Start Marine.command`，其他系统可在目录中运行 `.venv/bin/python tools/start_app.py`（先使用 uv 创建虚拟环境并按 requirements.local.lock 安装）。Mac 启动器自动安装36项锁定运行依赖，不安装训练工具，不要求 Java、Docker 或前端构建。

打开 http://127.0.0.1:8871/，点击“连接本地演示”。这是明确标注的本机合成身份；数据默认为空，可以创建自己的练习批次。服务仅监听回环地址，拒绝跨来源请求和不匹配主机。公网账号与真实业务部署需要独立生产配置。

macOS 数据目录为 `~/Library/Application Support/MarineFisheries/workspace`，权限0700；签名与加密密钥为0600且持久保存。升级与停止不会覆盖数据库、证据或旧运行资产。端口、数据目录和是否自动打开浏览器可通过 `--port`、`--data-dir`、`--no-open` 指定。`--check` 只读检查安装与模型状态，`--stop` 核对进程身份后仅停止本应用。

## 日常完整流程

连接 → 创建批次 → 上传加密证据 → 记录登陆、加工、冷链、交付等允许的状态 → 验证证据摘要与本地记录 → 查看批次历史。网络中断时保留原始请求，重新连接后按依赖顺序同步；队列中的冲突和超时保留明确的处理入口，可导出不含正文和身份的同步诊断。

本机模式的记录和摘要验证不会声称已经上链。Fabric/IPFS、Kafka/Flink、生产 OIDC 和真实设备仍需独立配置。没有外部服务时，界面保留明确的未接入状态，不伪造链回执或识别结果。

## 复用已有识别模型

本机模型放在数据目录相邻的 `models/norfisk/`：必须有 `model.onnx` 和同次导出的 `report.json`；可复用匹配的 `model-review.onnx` 和 `calibration.json`。它们只保存在本机，不进入 Release。若有公开实验的保留样本清单，放到 `models/protected-manifest.csv`，避免把验证/测试图像纳入人工训练池。启动器只使用这套明确选择的本机资产。

已有模型就绪后可以上传许可允许的图像，查看真实 ONNX 分类、置信度和校准状态，进行单独的人工复核。缺少模型明确返回未安装；不得把本机两类公开数据实验外推为目标海域、8鱼种或现场指标。没有重新训练、下载模型或恢复旧容器。

## 保留与恢复

Ctrl+C 或 `Start Marine.command --stop` 关闭服务；再次双击恢复同一数据库、证据密钥和历史批次。不要单独删除 evidence.key 或 jwt.key。安装包由明确提交的源码白名单构建，拒绝路径逃逸、链接和覆盖已有发布资产；启动前核对文件摘要。所有用例的现场效果、弱网设备功耗与生产链验收仍分别记录。


### 工作区入口与数据状态

页首可直接前往观测、图像识别、批次、数据录入和同步面板。入口只移动阅读位置与焦点，进入同步面板会展开原有详情，不提交或重试操作。空范围显示“当前范围暂无观测记录”，与已有但待更新、时间待核对的记录分开；没有预测时不猜测未训练等原因。升级只更新静态缓存版本，业务队列、身份隔离和加密证据保持原实现。

### 安装自检与升级

`--check` 读取已验证安装包的真实版本，只检查工作区与模型文件的存在性；`runtime: not-checked` 明确不把安装信息当作正在运行的版本。检查不删除或改写运行标记。升级时先停止当前版本，再启动新版，继续复用原数据与模型目录。

## 采集工单升级

新版本在现有 SQLite 中新增工单元数据表，不改写原业务表。已有工单时，不应切换到不支持该数据能力的旧版；本机版本切换入口会检查这一条件。旧安装与数据继续保留。

工单保存、断线重试和交接使用方法见[采集工单说明](collection-workorders.md)。本机单人会话仍可保存工单和录入，双人交接需已有成员身份；升级不会修改账号或私有配置。


## 核对来源数据

在“验收与复核”的“站点来源数据检查”中点击“检查所选站点的数据”。使用页面下方的站点与物种，检查范围在等待、完成或失败时都显示点击时保存的选择；修改选择会清除旧结果。检查按当前登录租户和站点查询最近记录，按所选物种分别计数，同时保留其他物种和站点环境记录。其他物种并不表示损坏，也不会改变多物种采集工单的选择规则。

本站点检查与上方工单验收分别处理：工单验收始终绑定所选工单的版本、来源和回执。站点检查没有发现所列问题，不能代替工单验收或独立审核；切换站点也不会修改工单或已保存的验收凭证。

检查项目包括事件契约、记录身份、规范化内容摘要（沿用存储规则，不含 receivedAt）、环境指标缺项，以及传感器自身的待核对/无效标记。结果只包含数量、固定问题类型和有界记录编号，不返回原始指标或事件正文。异常可通过链接进入现有来源与录入区域核对；没有自动修复或训练。

每次最多500条、累计1 MiB、单条8 KiB，详细定位最多32条；达到记录或字节上限时明确显示部分范围。只纳入能够识别站点的有界JSON记录，格式损坏、无法归属站点或超过单条上限的记录没有被计入，不能据此宣称全库通过。图片实体完整性、现场采集真实性、预测效果和外部链服务不属于本检查。

检查只在点击时执行；切换站点/物种、刷新来源、退出或离开页面会清除结果并中止请求。迟到响应不能覆盖新范围。接口为 `GET /v1/data-quality?siteId=...&speciesId=...`，使用已有会话和租户边界，响应禁止缓存；检查请求不修改业务记录。

当前源码在首次Store初始化时为既有事件建立查询索引，之后按租户、站点和时间直接定位；该一次性建索引会随历史记录数量增加启动耗时，但不会改写事件内容。已用包含损坏与超大记录的合成旧库验证，已有安装版和真实业务库尚未更新。

## 仪表盘离线快照

浏览器最多保留20份仪表盘快照。在线刷新成功后保留当前范围，再按保存时间保留其他最新范围；不按站点键名排序。没有有效保存时间的旧缓存先淘汰，时间相同按既有游标次序处理。离线读取仍要求同一身份、站点、物种和分页范围，以及24小时内的有效快照；没有缓存会明确提示。

快照写入与淘汰在同一个IndexedDB事务完成，失败或中止回滚，不先删除旧缓存。逐条游标读取，只保留最多19条其他范围的键和时间，不一次复制所有仪表盘正文。此容量规则仅用于可重建的`snapshots`存储，不删除离线队列、身份、工单、来源或验收凭证；不改变数据库版本或业务格式。

2026-10-29 在合成数据副本中通过真实API、SQLite与Chrome复现旧版近期范围被误删，并验证新版本的断网回看、20份上限、当前范围保留、并发保存、无效旧时间与事务中止回滚。原工单和成功凭证保持，零业务写入、模型、硬件、固定证据或账本调用。前端72项、Python101项分批通过，Ruff和构建通过；首次两项回环端口检查因本机权限失败，取得相应执行权限后单独补跑通过。远端检查以本轮交付回执为准；未替换安装版或部署。


## 当前 main 候选：准备依赖与日常启动分开

旧 `v0.4.1` 包的启动行为保留原版本。本节适用于包含 `Prepare Marine.command` 的当前源码候选，未发布新 Release。

首次安装或明确更新/修复时，先停止此安装正在运行的应用，再双击 `Prepare Marine.command`。它通过uv找到环境外的Python3.12，再重新建立环境，安装既有36项锁定依赖并核对文件；可能需要网络，也可复用uv本机缓存（`UV_OFFLINE=1` 时仅用已有缓存，缺包明确失败）。准备过程不启动应用、不下载模型、不更改工作区数据库或证据。失败时保留失败环境并恢复旧环境，不自动重试；成功也保留具名旧环境供核对。它们只含依赖，不是业务备份。每次开始前检查保留副本数量少于4、保留副本加当前环境最多2GiB/80000项，并为新环境预留576MiB；达到上限就停止，不自动删除成功副本。需先明确核对不再使用的依赖副本，再另行清理。强制杀死或断电留下准备标记时会拒绝再次准备，先核对安装进程和具名旧环境，不猜测完成状态。先核对原因再明确重跑准备。

日常双击 `Start Marine.command` 不调用uv、不创建环境、不安装依赖。已安装的Python先校验分发摘要，再按锁定版本检查安装包元数据与RECORD中的SHA-256文件摘要；缺包、版本不符、损坏、文件越出环境或超出边界时返回明确未就绪和准备入口，工作区尚未打开。检查最多128个依赖项、20000个有摘要文件、累计512MiB，不读模型和业务正文。它是本机安装一致性检查，不代替发行签名或对恶意修改整个环境的证明；RECORD自身与没有提供摘要的生成字节码不在文件摘要结论内。

`Start Marine.command --check-env` 只做离线环境检查，不创建工作区；原 `--check` 继续只报告安装/模型文件信息，`runtime: not-checked` 保持。缺少整个环境时直接提示先准备。正常运行持有安装环境共享锁，准备独占锁，拒绝边运行边重装；它们不改变其他安装或模型服务。准备中断会停止自己创建的安装子进程，保存既有数据；已成功准备的环境可在离线条件下再次启动。

已有工作区、加密密钥与模型目录继续复用，修复不会把数据清空。实际旧业务库/现场模型及其他平台需各自验收；本轮只验证独立合成安装与本机支持环境。
