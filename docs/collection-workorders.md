# 采集工单与交接

联网创建工单，选定已登记站点、启用设备和最多七天的时间范围。工单在服务端保存；
选择已保存工单可以继续查看，刷新不会重新生成观测。创建请求遇到断线时进入原有队列，
使用同一编号重试。原本仅在浏览器保存的作业保持只读，不自动导入或分配历史记录。

当前支持环境读数、渔获记录和批次登记的收件关联。已有观测作为来源时仍需明确选择。
图片分类登记成功后也通过来源选择关联；待人工复核的分类须发布后才可选。
来源列表刷新失败不会取消登记成功状态，也不要求重新识别或上传。
服务端重新检查租户、创建人及机构、设备、站点、时间、来源摘要和真实业务记录，
不接受客户端自称已成功的回执。批次后续流转与机构交接继续使用原业务流程。

离线记录保存在当前身份的队列中。业务请求已收件但工单关联失败时，页面显示
“业务已收件，待关联工单”。重试只补齐关联，保留原请求编号和已知收件凭据；
不会重新提交已经确认的业务。请求被修改、身份变化或工单已关闭时停止自动处理，
保留原操作供核对。重建操作不能覆盖已知成功结果。

创建人可在本机待同步记录清零后向另一名已有成员发起交接。待接收期间工单只读；
指定成员核对后独立确认，得到包含双方身份、时间、版本和内容摘要的交接回执。
创建人不能代替接收人确认；接收前可撤回，接收后不能改动工单。收件回执与交接回执
分别保存。工单交接不会自动转移批次的机构所有权，也不会宣称链上存证完成。

成员身份来自原有 RS256/OIDC 校验及本机可信成员映射。令牌自报的租户或角色不能扩权。
单人本机演示仍只有一个身份，界面不启用双人交接；配置和账号不会由升级程序自动添加。
本次双人流程用隔离签名身份验证，不能等同真实身份提供方登录、现场采集或生产部署。

## API 与限制

### 复用已保存的收件（2026-10-29源码）

打开可录入的目标工单，在“关联已有收件”中选择另一份可读取的原工单，读取收件后选择记录。勾选“同时关联原工单已声明的来源”会逐条重新核对来源摘要、站点和时间；不勾选时，目标工单必须已具备所需来源。环境读数仍要求目标设备一致。点击“关联到当前工单”只建立关联，不重做环境录入、渔获登记、批次创建、识别或采集。

原业务请求编号保持，新的关联使用单独请求编号。服务重新读取真实回执并核对所选摘要，记录原工单及其版本；原工单、业务内容和已有凭证保持不变。原收件已变化、仍待复核、目标已关闭、权限或范围不符时拒绝，来源复制与关联在同一事务中回滚。相同关联请求可以重试；结果未确认时先刷新目标工单，若已存在相同收件则直接确认，无需再次提交。结束工单与独立验收仍分别执行。

`GET /v1/collection-orders/{id}/record-receipts`只返回最多128条收件和100条来源元数据，不附带交接快照、文件或业务正文。`POST .../records/reuse`接收新的`requestId`、目标`expectedRevision`、`sourceOrderId`、原`sourceRequestId`、`path`、`recordId`、`evidenceHash`及严格布尔`includeSources`。原`records`接口及其幂等摘要保持兼容；不新增表或迁移。页面仅保留一份原工单元数据，切换身份/目标会中止旧读取，未知关联不触发业务重做或新的后台轮询。

- `POST/GET /v1/collection-orders` 创建或分页读取工单，详情使用其编号。
- `POST /v1/collection-orders/{id}/sources` 明确关联来源及其已读摘要。

- `GET /v1/collection-members` 只列出同租户可接收成员的必要标识。

## 独立验收与历史凭证（当前源码）

采集结束、工单交接、验收通过分别记录。新流程为：只读检查本工单引用 → 创建人明确保存检查 → 另一名授权审计员核对并通过或退回 → 导出有完整性摘要的历史凭证。不会因结束采集而自动通过验收，也不会自动固定文件、提交账本、训练或重新采集。

检查复用来源数据质量规则，但只查本工单最多100条来源、128条收件记录，不扫描全站其他历史。核对设备/站点有效性、来源格式与摘要、环境缺项/待核对标记、收件绑定、业务待复核状态、关联批次召回及未关闭冷链异常。未结束、缺失、超大、无效或超出容量均不作通过结论。检查前可先结束采集；站点/设备问题沿用原登记修正，已关闭工单的错误原件保持历史，可新建工单复用有效收件，不能把错误原件覆盖成通过。

证据等级需明确选择：

- **本机来源与收件回执**：只确认所列本机数据和原回执，不要求额外远端服务。
- **每批次至少一份已有固定证据**：关联批次至少一份证据已有匹配租户/批次的固定状态与CID。
- **每批次已有账本确认及确认的证据**：批次命令均有已保存确认回执，且至少一份证据已有 `COMMITTED` 和有效确认标记。

后两种等级只读取已经保存的确认，不实时查询IPFS/Fabric，也不证明远端此刻可用。检查不读取实体图像或重新核对原图；这些范围在响应中明确标为未检查。

保存的检查固定工单版本、来源/收件/相关元数据摘要和证据等级。审核时再次在同一事务快照核对；变化则拒绝旧检查。审核人须为另一名当前授权审计员，创建人即使后来改成审计员也不能自审。每份检查只有一个不可覆盖的决定；网络重试复用同一请求编号。退回原因、历史检查和原决定保留。只读页面可查看当前绑定是否变化；旧通过凭证仍可作为历史导出，并明确提示当前已变化。

凭证的摘要覆盖冻结检查与决定。浏览器在下载前按JCS规范复算SHA-256；这用于发现内容改动，不是数字签名或离线作者认证。导出时的“当前状态”另列在冻结凭证之外，不冒充历史决定的一部分。需要依靠原有租户/机构授权重新读取服务端记录。

每工单最多8份检查；单份元数据128 KiB、定位32条、输入元数据2 MiB、关联批次32个、每批次证据16份、账本命令1000项。达到边界会阻止完整通过，不静默截断。每租户最多10000份/64 MiB检查，满后停止新增，不自动删除历史。界面只保留当前检查与最多8条目录，无新增轮询；身份、工单或等级变化以及离开页面会取消并失效旧响应。后台刷新会保留仍在当前授权目录内、用户刚选中的工单。

API：`GET /v1/collection-orders/{id}/acceptance-preview`；`POST/GET .../acceptance-assessments`；`GET .../acceptance-assessments/{assessmentId}`；`POST .../{assessmentId}/decisions`；`GET .../{assessmentId}/certificate`。所有读取与决定都经过现有租户/成员授权，写入要求请求编号和乐观版本。初始化只追加检查与决定表，不修改来源、业务、工单或旧回执。

方法独立借鉴 [ODK Central 的提交复核状态](https://docs.getodk.org/central-submissions/)，将采集收件、人工审核与可携带历史证据分开。未复制上游代码，未安装ODK服务。本轮只交付源码并使用隔离合成库验证，没有更新安装包、操作真实业务库或部署。


### 分区查阅

“采集与录入”用于打开工单和填写观测；“验收与复核”显示当前选定工单及版本，独立读取既有检查和凭证。两个分区共用同一工单上下文，切换不会创建、关闭、移交或验收工单。首要操作仍由当前权限与保存状态决定；无选定工单时，验收区先给出选择入口。已有内部锚点继续定位到对应分区，尚未提交的字段保持。


## 2026-10-30 工单进度与下一步

打开工单后，旁边会显示已关联来源/回执、本机待同步和业务收件待关联的数量。
下一步入口根据当前工单与已加载证据指向来源、结束工单、验收或接收位置；
跳转不自动提交业务、重试、结束或批准。同步入口会选中当前工单对应的原队列项。

只有读取到当前身份、该工单及当前版本的有效独立审核，才显示验收通过。
历史、过期或其他工单的审核不用于当前结论；离线状态显示缓存边界。
观测首页没有有效缓存时只清除不可用的观测与批次视图，保留同一身份的工单、
录入和待同步记录，避免保存后被误显示成丢失。退出或身份切换继续执行完整清理。

进度投影复用已加载的工单与有界队列，不增加轮询或背景业务请求。验证使用合成
副本与原有成功回执，未重新采集、识别、固定证据或提交账本，也未连接现场硬件。


## 2026-10-30 未提交输入与工单归属

工单新建表单、环境读数、渔获、批次和待关联来源会记录轻量的输入归属，
包含当前身份范围、工单、版本与站点设备，不复制正文或文件。
切换工单、新建或改变相关筛选时，未提交输入要求明确保留或放弃；
只有目标工单成功读取且期间没有新编辑，才清理原表单。失败或取消保持输入。
放弃仅清理表单，不删除已持久化队列、回执或工单。结束/交接前也须处理未提交输入。

同一工单的版本或来源更新时，文本与数量保留，先核对最新信息、重新选择来源，
再继续提交。另一份工单不能直接继承旧输入；原先未绑定工单的输入须明确选择绑定。
读取元数据期间的新编辑、身份变化和工单切换会使旧确认失效。
已入本机队列的操作继续沿用原 scope、工单 ID 与请求 ID，不重新归属或重复发送。

这一保护范围不改识别器、已成功识别资产、证据上传与账本流程；没有新增轮询、
文件缓存或输入持久化。输入归属最多跟踪五个表单/选择器，退出页面解除监听。
