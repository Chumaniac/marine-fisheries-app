## 本轮发现并补齐的遗漏

- 数据录入原先主要依赖接口/脚本：补齐站点、设备、环境、渔获、JSON导入和预测来源入口。
- 离线新批次原先不能继续选中流转，连续操作版本也不正确：显示待同步批次并顺序推演状态和版本；服务器确认与本机待同步状态分开。
- 交接原先缺少可操作的接收列表，拆合批只支持单输入/单输出：保留申请编号、按机构列出待接收申请，支持多输入和多输出。
- 冷链超限原先没有“拦截—处置—继续”的完整流程：新增暂停送达、处置依据与加密证据；实际发现被拦截的送达队列也阻塞处置，已改为独立提交处置，再重试原送达请求。
- 证据选中项原先可能跨批次沿用：绑定批次和身份，换批次时清除旧选择。浏览器确认未选择当前批次证据时拒绝下载。
- 原先缺少便捷原件下载和完整存证入口：补齐观测图像、复核图像、普通证据下载及一次完成副本、上链和核验；图像下载保留可直接打开的PNG/JPEG类型。
- 预测更新后旧快照与新模型容易混淆：分别显示当前模型、该次预测使用模型、发布时间、有效期和来源数量。切换站点后刷新来源，失效关联不会静默转成手工记录。
- 状态/交接的409冲突可以核对最新状态后明确重建，旧请求保留；未知结果继续核对原请求。其他非法录入保留记录并提示在原表单修正，不自动猜测业务决定。

## 直接使用

打开本地工作台 `http://127.0.0.1:8871/`，连接本地会话。查看预测选择站点 `forecast-cycle-1791771257`、物种 `saithe` 后刷新；查看完整供应链选择加工机构与批次 `user-final-merged`，查询溯源并核对账本。历史预测已经过期，页面保留来源并提示，不自动伪造新鲜数据。

录入新业务先登记站点/设备；同一站点内选择鱼类与环境来源，再填写实际渔获和作业量。仅在具备已授权数据时选择“现场记录”。页面机构切换用于本地演示，生产环境使用真实机构登录。
