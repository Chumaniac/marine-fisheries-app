## 识别实验

官方 [NorFisk](https://doi.org/10.18710/H5G3K5) 页面列 CC0。标签是 saithe 与合并的 salmonids 两类，后者包含鲑与鳟，不是两个精确物种的细粒度分类。准备了 4,713 张裁剪图：训练 3,281、验证 777、测试 655。

原始视频编号不可得，因此按文件名块分组、留边界间隔并去精确重复。这不能证明鱼个体、航次或站点完全隔离，近重复和背景相关性可能使结果偏乐观。

| 指标 | 实际结果 |
| --- | --- |
| 测试 accuracy | 98.7786% |
| 测试 macro-F1 | 97.8148% |
| saithe 召回 | 100%，106 个样本 |
| salmonid 召回 | 98.5428%，549 个样本 |
| 相同增强特征的交叉熵基线 accuracy | 98.9313% |
| 基线与选定模型错误数 | 7 与 8 |
| 最佳验证配置 γ | 0，即带权交叉熵 |

没有证明 Focal Loss 改善结果，也没有实现误判下降 60%。不能用两类公开数据的 98.78% 宣称原目标场景已超过 92.3%。60 次搜索针对冻结 B0 的分类头；随后尝试末两阶段微调并按验证集选择，并非 60 次完整骨干训练。

证据：[模型报告](evidence/classification-report.json)、[逐条预测](evidence/classification-test-predictions.csv)、[60 次试验](evidence/optimization-trials.json)、[数据来源](evidence/dataset-provenance.json)。

## 量化与边缘性能

FP32 ONNX 约 16.0 MB。第一版 INT8 约 4.4 MB，验证 macro-F1 为 60.43%；逐通道 INT8 约 4.8 MB，验证 macro-F1 为 85.54%。两种候选均未通过不超过 1 个百分点精度损失的门槛，**都没有替换服务主模型**。

本机 CPU 验证样本暖推理 p95 约 9 ms（FP32），INT8 约 6–8 ms；不含摄像头、检测跟踪、网络及功耗。另一次 20 张预处理/推理调用均值约 28.8 ms，含首次冷启动的最大值约 410 ms。没有宣称真实边缘设备达到 250 ms。

证据：[第一版 INT8](evidence/int8-first-candidate.json)、[逐通道 INT8](evidence/int8-perchannel-candidate.json)、[CPU 烟测](evidence/onnx-cpu-smoke.json)。

## 流处理和预测

Flink 从实际 Kafka 读取事件、生成分钟窗口，由独立消费者落到 SQLite。应用返回 `featureSource=flink-minute-windows`。极晚事件进入独立 topic，不覆盖当前窗口。

水位线在 Kafka source 设置以保留分区进度，空闲分区阈值为 2 分钟。调整前保留原作业 savepoint，新拓扑在本地通过 Kafka 日志与幂等读模型重建，未宣称生产无损升级。

实际组件检查确认：同一事件发送两次只计数一次，超迟到事件进入旁路。消费者修复了全局 commit 提前确认其他分区的问题，原子条件更新防止旧重放覆盖新计数或水位线。[实际流检查](evidence/stream-recovery-check.json)

合成 CPUE 的滚动回测 WAPE 为 4.299%、区间覆盖约 94.74%。数据由公式和噪声生成，**不是海洋渔情准确率 85.4% 的验收**。[合成报告](evidence/synthetic-regression-report.json)

Kafka 仅供受信任的本机服务写入；租户没有直接 broker 访问入口。tenantId 本身不是认证机制，生产必须增加服务身份、ACL/TLS和设备绑定，不能公开本地 broker。

当前为单 broker、单并行流任务和本地 SQLite，没有生产 HA、跨主机灾备和大规模吞吐验收。标签责任方须保证作业量、成熟时间及特征来源真实，接口字段不能证明源头无造假。

## 前端与弱网

`web/` 使用真实 ECharts/API；`showcase/` 是原始概念展示。没有授权坐标时地理图为空。站点与物种隔离查询、模型和浏览器缓存。

缓存和待同步操作绑定 tenant、subject、权限范围及身份租期。Cookie 写请求绑定当前身份范围，服务器拒绝旧范围；退出清除显示和缓存、保留未确认操作，原身份恢复后才同步。已知验证/测试集图片被排除出人工训练池。

浏览器实际暂停原生服务后，缓存页面仍可刷新，新批次留在 IndexedDB；恢复会话后队列 1→0，批次入库。该检查验证本地服务中断，没有模拟真实海上 RTT、带宽、丢包或 72 小时离线。此前被用户中断的浏览器网络注入没有结果，不列为通过。

页面、样式及 ECharts bundle 的 gzip 总量约 196 KB，另加 API 响应；脚本约 192 KB，未达到初始脚本≤100 KiB 子预算。少量本机 LCP 不是 p75，也不能证明 4.2 秒降到 1.5 秒。

## 尚未满足的整体条件

- 目标海域与鱼种的真实采集、人工标签、视频/航次分组和域外测试。
- 真实渔获、标准作业量、环境时间序列与授权坐标，用于无泄漏回测及区间校准。
- 人工标注计时与对照，才能判断是否节省 40%；自动选样数量不能代替人工工时。
- 真实边缘设备、相机、弱网、断电、功耗、热稳态与长期内存验证。可靠检测跟踪和实海计数还需专项实现，当前图像接口是单鱼分类。
- 生产身份与设备站点绑定、机构证书、五方网络、多副本、备份恢复，以及目标云环境的函数部署、告警和性能验收。
- 相同保留期、可用性和副本条件下的实际账单，才能验证降本 70%。

上列条件尚未完成。需要真实数据、设备、机构参与和明确部署环境，不能通过继续生成合成数据或反复调测试集补齐。
