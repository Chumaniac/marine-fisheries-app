# 本地证据部分提交与核对

文件写入、SQLite提交、IPFS副本和Fabric回执是不同边界。本轮只补本地保全和只读核对，不提供自动重放交易或删除历史密文的功能。

## 数据库和密文

本地采集、复核、直接证据上传与业务命令使用隔离的事务作用域。新密文在发布前限制256KiB原文、同步内容与目录，使用不覆盖已有对象的发布方式。SQL提交失败时，另开只读连接检查固定证据表：只有本次创建、文件身份和摘要未变、且确定没有引用的对象才会移除。退休前先捕获实际目录项到本次私有目录，再验证身份和内容；同名文件被替换时不删除，尝试不覆盖地归还并保留捕获材料。提交已成功而确认丢失、数据库不可读、元数据异常或核对超时都保留材料。

成功事务不做全表恢复扫描；并发进入相同受理流程会在持有写事务后重查既有证据，避免创建一个被`INSERT OR IGNORE`丢弃的对象。作用域通过ContextVar隔离，不能跨请求或任意后台任务延续；最多跟踪64个新对象，失败核对总时间预算2秒。

密钥只从普通、私有的32字节文件读取。若对象目录有旧材料，或数据库已有证据引用，缺少密钥时拒绝创建新密钥；损坏或不安全权限同样拒绝，不静默重置。请恢复原始密钥和完整备份，不能生成一个“替代密钥”来解密旧数据。

## 受理回执

`GET /v1/edge-samples/{sample_id}` 仍按tenant和设备授权，但会结合证据记录、复核链接与最终事件返回 `phase` 和 `nextAction`：

- 已受理或证据保存后处理失败：`action_required`，保留原ID，先核对原请求。
- 有排队复核：`review_pending`，等待人工。
- 人工复核已提交、事件尚未发布：`reviewed_publication_pending`，核对原请求，不要求再次标注。
- 最终事件只有在tenant、device、evidence绑定正确且证据记录存在时才报告published；同ID不同证据不会冒充成功。

这些phase是本地数据库事实，不等同密文完整性验证、IPFS可用性或链上VALID回执。重试必须使用原请求及幂等身份，不能换ID重复处理；原Fabric未知状态继续走已有回执对账，不因本轮改动而自动上链。

## 只读观察

```sh
cd /absolute/private-parent
python -m marine.evidence_recovery --root workspace --limit 256
```

仅在本机操作上下文内读取数据库与对象目录元数据，不读取密钥、不解密、不删除、不上传。默认最多观察256项，上限10,000项；核对预算2秒，超量/超时/不能确认会返回 `complete: false` 或 `unconfirmed`。返回的是引用分类计数，`checksContentHashes: false`，不能把“有引用”当作已经验证内容正确，也不能把“无引用”当作删除授权。

旧孤儿、部分临时文件和未知结果先保全并单独归档。已建立的数据库/对象备份工具仍用于新目录恢复并验证哈希和解密；不能拿这个观察命令替代恢复演练、真实机构证书、实际海上弱网或生产接受。本轮验证只有隔离合成SQLite/密文、服务调用和发行包，不访问真实航次、模型服务或联盟链。

对象和主目录需要当前用户所有权且不能组/全局可写；不自动更改既有权限。同一OS用户仍能恶意篡改应用文件，这不是进程沙箱边界。目录迁移、介质恢复和密钥操作应停服务。私有捕获目录出现时只读观察会标记other/不完整，不能自动删除其中内容。
